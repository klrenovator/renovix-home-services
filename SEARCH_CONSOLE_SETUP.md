## 1. Why this matters for leads

Search Console is Google's own account of the site. It is the only place to see:

- **whether Google has read `/sitemap.xml`** and how many of its URLs it knows;
- **the exact queries** people type before they land on a page — the raw
  material for deciding what content to write next;
- **indexing problems while they are still cheap to fix** (a page silently
  excluded from search costs leads every single day it stays excluded);
- **whether the pages that ask for a quote are being crawled** at all.

```
Query in Google → indexed page → visitor → call / WhatsApp / quote form → lead
                  ▲
                  └── nothing after this point happens for pages Google has not indexed
```

## 3. Confirming verification and submitting the sitemap

### Step 1 — Use the business's own Google account

Search Console access is account-based. Use the account the website
verification file was created for; if someone else set it up, ask them to add
the business as an **owner** (Settings → Users and permissions), never as a
new property.

### Step 2 — Check which property exists

Two property types are possible for this site:

| Property | What it covers | Note |
| --- | --- | --- |
| **URL prefix** — `https://renovixhomeservices.my/` | Exactly this host and path prefix | The one the deployed HTML file verifies. It is already in the repository and served (table above) |
| **Domain** — `renovixhomeservices.my` | Every subdomain and both protocols | Only if the owner can add a DNS TXT record at the registrar. Optional; do not add it just to have it |

**Check the hostname in the property selector.** The site's canonical host is
the apex `https://renovixhomeservices.my/`; the sitemap and page canonicals
use that host. `www.renovixhomeservices.my` is an alias configured to redirect
to the apex. If the URL-inspection bar says
`https://www.renovixhomeservices.my/`, you are viewing the separate **www
URL-prefix property**, not the canonical apex URL-prefix property. Switch to
the existing apex property (already recorded as verified), or use an existing
Domain property if the owner has one. Do not create another property or
re-submit the sitemap. A www-prefix view alone is not the site's canonical
property view.

If neither canonical property exists, add the **URL prefix** property and
verify it with the **HTML file** method — the file is already deployed and
serving, so Google's check passes immediately.

### Step 3 — Submit the sitemap (once)

Indexing → Sitemaps → enter `sitemap.xml` → **Submit** (the full URL is
`https://renovixhomeservices.my/sitemap.xml`; the field wants the path only).

Submit it **once**. Repeated submission does not speed anything up and makes
the status history harder to read. Google re-reads a submitted sitemap on its
own schedule, and `robots.txt` also points crawlers at the same file.

### Step 4 — Read the status honestly

| Status shown | What it means | What to do |
| --- | --- | --- |
| **Success** | Google fetched and parsed the file on the date shown | Nothing. Open §4 |
| **Couldn't fetch** | Google could not download it | Re-run `npm run verify:search-console -- --live`. If that passes from your machine, wait 24–48 h and check again — Google's fetch happens from its own network |
| **Success with 0 discovered URLs** | Usually the first few hours, before processing finishes | Wait a day; then re-check |
| **Sitemap contains URLs which are redirects** | A listed URL answers with a 3xx | The sitemap emits only 200/trailing-slash URLs, so this means deployment drift: re-run `npm run verify:search-console -- --live` and compare `npm run audit:sitemap` |
| **Sitemap could not be read** | Wrong content type or malformed XML | The live check asserts `application/xml`; if it fails, the deployment is not the one this repository describes |

### Step 5 — Ask Google to crawl the pages that ask for quotes

Open **URL Inspection**, paste the URL, and read the verdict. Use
**Request indexing** only for pages that are not yet indexed and matter to
leads — for example:

- `https://renovixhomeservices.my/en/` (and `/ms/`, `/zh/`)
- `https://renovixhomeservices.my/en/quote/`
- `https://renovixhomeservices.my/en/services/waterproofing/` (or whichever
  service you are actively selling)
- the area page for a locality you are targeting, e.g.
  `https://renovixhomeservices.my/en/areas/kuala-lumpur/mont-kiara/`
- the problem page behind the query you most want to win, e.g.
  `https://renovixhomeservices.my/en/problems/water-leakage/`

Request indexing is a hint, not a guarantee, and the property has a small
daily quota. Asking repeatedly for the same URL does nothing.

### Step 6 — Link Search Console to GA4

**Search Console → Settings → Associations → Google Analytics → Link**, then
confirm in GA4 under **Admin → Product links**. This lets queries and on-site
lead actions (WhatsApp clicks, quote submissions — see `ANALYTICS_SETUP.md`)
be read side by side instead of guessing which query produced an enquiry.

## 4. What "processed" looks like over time

| Time since submission | What to expect |
| --- | --- |
| Minutes | Property verified; sitemap appears in the list as *Pending* |
| Hours to ~2 days | Sitemap status becomes **Success** with a discovered-URL count |
| Days | Pages move from *Discovered* to *Crawled*; the **Page indexing** report starts filling |
| 1–3 days after first impressions | **Performance** starts showing queries and impressions (there is a reporting lag) |
| Weeks | Indexing stabilises; rank data becomes stable enough to compare months |

Google indexes pages it judges worth indexing. A new site with no external
citations (see Task 3.3) can take weeks — that is normal and is not a defect in
the sitemap.

## 5. What to read every month (this is where leads come from)

1. **Performance → Queries** — sort by impressions. Queries with many
   impressions and few clicks are title/description problems; queries you do
   not have a page for are the next content to write.
2. **Performance → Pages** — which pages already attract search demand; make
   sure each one carries a quote CTA and a WhatsApp CTA.
3. **Performance → Countries/Devices** — confirm Malaysia and mobile dominate;
   a mobile-heavy profile is what the site's mobile CTAs are built for.
4. **Page indexing** — any URL excluded for a reason you did not choose
   (404, noindex, redirect) is a fixable lead leak.
5. **Core Web Vitals** — compare to the field data the site already reports
   (`PHASE_24_ANALYTICS.md` §5); slow pages lose mobile visitors before the CTA.
6. **Security & Manual actions** — should always be empty; check anyway.

## 6. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Sitemap status stuck on *Pending* | Google has not re-fetched yet | Leave it; re-reading happens on Google's schedule |
| *Couldn't fetch* while the live check passes | Google's fetcher saw a transient error, or a CDN/edge rule blocked it | Wait 24–48 h, then check again; ensure no bot-protection rule blocks `Googlebot` on the apex host |
| Pages indexed under `www` instead of the apex | A `www` URL was linked or submitted somewhere | Keep the apex as the canonical host in Vercel's domain settings (already the site's canonical shape); request removal of `www` duplicates only through Search Console's own tooling |
| *Discovered — currently not indexed* on many pages | Normal for a young site with few citations | Keep adding genuinely useful content and earn citations (Task 3.3); do not mass-resubmit URLs |
| *Duplicate, Google chose a different canonical* | A canonical/hreflang mismatch | The site writes absolute trailing-slash canonicals; run `npm run audit:sitemap` and `npm run audit:multilingual` and fix any drift at the source |
| Impressions but almost no clicks | Titles/descriptions not matching intent | Improve the page title and opening paragraph for the exact queries Search Console shows |
| Performance shows nothing at all | Too early, or the property is the wrong one | Check the property selector; give it 1–3 days after the first impressions |
| GA4 shows the visit but Search Console shows no query | Queries are only shown for some searches (privacy and volume thresholds) | Read GA4 for *conversions*, Search Console for *queries* — link them (§3 step 6) |
