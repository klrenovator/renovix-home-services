# Sitemap & robots.txt — how it works, how to operate it

Production domain: **https://renovixhomeservices.my**

| URL | What it is |
| --- | --- |
| `https://renovixhomeservices.my/sitemap.xml` | The site's single, canonical sitemap (native Next.js `app/sitemap.ts` route) |
| `https://renovixhomeservices.my/robots.txt` | Generated by `app/robots.ts`; references the sitemap above |

The old per-language sitemap URLs (`/sitemap/en.xml`, `/sitemap/ms.xml`,
`/sitemap/zh.xml`) were retired when the sitemaps were consolidated. They
return a permanent (308) redirect to `/sitemap.xml`, so any crawler or Search
Console entry that learned them keeps working.

## Automatic URL discovery — there is no URL list to maintain

The sitemap is generated from the same content registries that generate the
pages themselves (`i18n/coverage.ts` + the `data/*` registries). Adding any of
the following automatically adds the URL(s) to `/sitemap.xml` on the next
deploy — nobody edits a sitemap array:

- a **service** → `data/service-content/` + registry entry
- a **problem page** → `data/problem-content/`
- an **area / region page** → `data/area-content/`
- a **project** (published) → `data/project-content/`
- a **translation** of any of the above → the page's URL appears in that
  language's set and in every hreflang alternate set
- a new **language** → `data/languages.ts`

A build-time guard (`assertCoverageInSync()`, run when the sitemap is
generated) fails the build if the registries drift, so a stale slug can never
produce a sitemap entry for a URL that would 404.

## What is excluded (by construction)

The sitemap only ever contains public, canonical, indexable page URLs derived
from the registries. It structurally cannot contain: `/api/*`, admin /
dashboard / login / test / preview routes (none exist), 404 & error pages,
redirect-only URLs (the bare `/` root redirects to `/en/` and is never
listed), `noindex` pages, query-string or tracking variants, non-canonical
trailing-slash variants, and draft (unpublished) projects. Every entry is
`https://`, on the production domain, in the exact trailing-slash shape the
site serves — verified: all sitemap URLs return 200 and each page's canonical
tag matches its sitemap `<loc>`.

## `lastModified` policy

The registries carry no per-page timestamps, so all entries share one
**reviewed content date** (`CONTENT_LAST_MODIFIED` in `lib/sitemap.ts`). It is
bumped by hand when page content materially changes — it is never set to "now"
per request or per build, because stamping unchanged pages with a fresh date
would misrepresent them to crawlers. If the data model ever gains real
`updatedAt` values, use those instead and delete the constant.

## Google Search Console — one-time setup only

1. Submit **`https://renovixhomeservices.my/sitemap.xml`** once. That is the
   only sitemap submission this site ever needs.
2. If per-language sitemaps were submitted in the past, remove those entries;
   the old URLs now redirect to the main sitemap anyway.

That's all. After that:

- New pages appear in `/sitemap.xml` automatically on each deploy, and Google
  re-fetches the sitemap on its own schedule (helped by the `Sitemap:` line in
  `robots.txt`).
- **Discovery ≠ indexing.** Being in the sitemap makes URLs easy for Google to
  *discover and crawl*; it does not guarantee indexing. Google independently
  decides whether and when to index each URL (quality, duplication,
  canonicalization, crawl budget, spam signals all factor in). No submission
  pattern changes that.
- Do **not** use sitemap "ping" endpoints (`/ping?sitemap=…`) — Google
  deprecated them in June 2023. No code here calls them.
- No Google API keys, OAuth tokens or service-account credentials exist in
  this repository, and none are needed. (A Search Console *API* integration
  could submit sitemaps programmatically, but it would only ever be an
  optional, server-side addition — credentials in env vars, never in the
  frontend — and is unnecessary for this architecture.)

## Scalability

One sitemap file comfortably covers the whole site (633 URLs today; Google's
limit is 50,000 URLs / 50 MB uncompressed per file). If the site ever
approaches that limit, split into child sitemaps + a sitemap index — see the
note in `app/sitemap.ts` for the Next.js 16-specific constraints (the split
must replace `app/sitemap.ts` with route handlers; adding
`app/sitemap.xml/route.ts` alongside `app/sitemap.ts` fails the build).
